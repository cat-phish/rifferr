# Backlog

Ideas, issues, tech debt and open questions that come up while building and
are **not** part of the current task. Append here instead of acting on them.

## Rules
- One entry per line, in the section that fits:
  `- B-<NNN> [idea|bug|debt|question] (YYYY-MM-DD, from <spec ID or "session">) Summary.`
  Extra detail goes on indented lines below the entry.
- IDs are never reused. Take the next number after the highest in the file.
- When an entry is picked up, turn it into a spec, a spec *Open question*, or a
  spec task, then move it to **Done** with a pointer (`→ S-SHELL`, `→ 1a2b3c4`).
- List or filter: `python3 scripts/spec.py backlog [--tag question] [--section Ideas]`.
  `spec.py lint` checks IDs are unique and well-formed.

Confirmed 2026-11-11 by `test_BEETS_IMPORT_12_regex_query_needs_quotes_for_backslashes`: unquoted backslashes are lost. Still to do: fix the docs example to quote the regex term and consider a UI hint.
- B-031 [bug] (2026-11-12, from C-CHANGESET) A `cancel_run` that reaches the worker after it claimed the job but before the engine exists (`Worker._run` is still None) is dropped, and a cooperative step then runs on. Seen as a timeout in `test_WORKER_5_cancel_a_queued_run` under load, and once in `test_API_6_queued_run_shows_pending_steps` (2026-11-12, S-TAGSCRIPT batch run; passes alone). Likely fix: remember the cancelled run id and cancel it as soon as its engine is created (or check the job row before executing).
  2026-11-12: also seen in CI (py3.12 job, run 43277485853) as `assert 'running' == 'cancelled'`.
- B-032 [bug] (2026-11-12, from session) On a NixOS dev machine, `tests/steps/test_shell.py` (9 tests) fails because the shell harness sets `PATH=/usr/bin:/bin`, and NixOS has no `tr`, `pwd` etc. there. Also, beets' `lap`/numpy wheels need `libstdc++.so.6` and `libz.so.1` on `LD_LIBRARY_PATH` (see B-012), and `pnpm` is only available through `corepack pnpm`. No Playwright browser is installed, so `pnpm e2e` (`two-step.spec.ts`, `tagscript.spec.ts`) can't run there. Consider building the test PATH from `shutil.which` results, and documenting the Nix setup.
  2026-11-12: on the Fedora desktop all 952 backend tests pass, including the shell tests, so this is NixOS-only. On that desktop a zsh alias made `uv` launch an editor, so `pnpm e2e` needs `UV=<path to uv>` (`e2e/global-setup.ts` reads `UV`).
- B-035 [bug] (2026-11-12, from S-TAGSCRIPT) In beets, an item-scoped template or condition still sees the stored album's value of a flexible attribute that an earlier album-scoped action in the same script deleted, because beets items fall back to their album for fields they don't have. Rare; fixing it means overlaying the album's working values too (the evaluator would pass them to `evaluate`/`matches`).
- B-036 [bug] (2026-11-12, from session) `backends/beets/apply.py` finds effects and items to write by walking each target's album, so a ChangeSet on a singleton item (no album) would store the DB change but report no effects (the journal couldn't undo it) and write no file tags. Not reachable yet, because proposals must target albums from a snapshot. Handle albumless items before singleton imports can be edited, and add a contract test.
- B-037 [bug] (2026-11-12, from S-REVIEW) The server and the worker both append events to a run's stream with `seq = last_seq + 1`. If both write at once (e.g. a user cancels a run while its `review_reject` undo job is logging, or a ChangeSet decision races `supervisor.cancel`), one event is dropped as out of order ("dropping out-of-order event"). Rare; a fix would route all of a run's events through one writer or retry with the next seq.
